# Entity Collision Grid

Fabric-мод для Minecraft **1.21.11**: заменяет перебор сущностей при запросах коллизий/толкания/«давки» (cramming)
на **spatial hash grid** (broad-phase). Работает и на клиенте, и на сервере (`environment: *`).

## Что делает
Ванильный `World.getOtherEntities(Entity, Box, Predicate)` (его используют `getEntityCollisions`, `getCrammedEntities`,
толкание мобов и т.п.) просматривает **всех** сущностей каждой 16×16×16-секции в окне поиска. В секции с 50+ мобами
каждый запрос — это десятки проверок, а у каждого моба такой запрос каждый тик (≈ O(n²)).

Мод ведёт для каждого мира сетку ячеек (по умолчанию 2×2×2 блока), в которой каждая сущность записана во все ячейки,
которые перекрывает её хитбокс. Запрос берёт только сущности из ячеек, перекрытых искомым `Box`, и точно проверяет
пересечение уже у них. **Результат совпадает с ванильным** (те же секции-окна и статус отслеживания чанка, те же
предикаты, части дракона Края обрабатываются как в ваниле).

Где что подключено (найдено по декомпилированным Yarn-исходникам 1.21.11):
- `World#getOtherEntities` — `@Inject` в HEAD (cancellable), приоритет миксина **1500**;
- `EntityTrackingSection#add/remove` — заполнение/очистка сетки (точное зеркало списка сущностей в секциях);
- `Entity#setBoundingBox` — единственное место, где присваивается хитбокс (движение, поза, размер) → обновление ячеек;
- `World#close` — очистка сетки при выгрузке мира.
Не затрагиваются: `Entity#updateMovementInFluid` и любые методы жидкостей/тегов блоков.

Страховки: если запрос выполняется не из «своего» потока, бокс слишком большой (> `maxQueryCells` ячеек), запрос
вложенный, либо `EntityLookup` подменён другим модом — выполняется обычный ванильный код.

## Требования
| | версия |
|---|---|
| Minecraft | 1.21.11 |
| Fabric Loader | ≥ 0.19.5 |
| Fabric API | 0.141.x+1.21.11 (любая для 1.21.11) |
| Java | 21 |
| Sodium (опционально, для меню) | 0.8.x (проверено на 0.8.14) |

Установка: положите `dist/entity-collision-grid-1.0.0.jar` в `mods/`.

## Настройка
**Через Sodium** (Настройки видео → страница **Entity Collision Grid**; используется публичный Config API Sodium 0.8,
entrypoint `sodium:config_api_user`, как у Iris): включение, размер ячейки (1–8 блоков), отладочный лог, сверка с ванилью.

**Без Sodium** — файл `config/entity_collision_grid.json`:
```json
{
  "enabled": true,
  "cellSize": 2,
  "debugLog": false,
  "debugVerify": false,
  "debugIntervalSeconds": 15,
  "maxQueryCells": 512
}
```
- `cellSize` — размер ячейки в блоках (1–8). Меньше — меньше кандидатов, но больше учёта у крупных сущностей. Менять можно «на лету»:
  сетки перестраиваются сами. (Sodium API у 0.8.x есть, поэтому Cloth Config как запасной вариант не понадобился.)
- `debugLog` — раз в `debugIntervalSeconds` пишет в лог, сколько проверок сделала бы ваниль и сколько сделала сетка; при старте
  запускает синтетический бенчмарк.
- `debugVerify` — дополнительно выполняет ванильный запрос и предупреждает при любом расхождении (медленно, только для тестов).

## Бенчмарк и результаты
Юнит-тесты (`./gradlew build` запускает их): 50/100/400 мобов в одной области 14×14 блоков, каждый спрашивает «кто касается моего хитбокса»:

| сущностей | проверок ваниль | проверок сетка | меньше |
|---|---|---|---|
| 50 | 2500 | 172 | 93.1 % |
| 100 | 10000 | 654 | 93.5 % |
| 400 | 160000 | 8582 | 94.6 % |

Тест на реальном выделенном сервере 1.21.11 (≈95 коров/овец на форсированных чанках, `debugVerify=true`): ≈ −87 % проверок
(−43 % в момент самой плотной давки), **0 расхождений** с ванильным результатом на десятках тысяч запросов.
Цель «−30…40 %» превышена с запасом. Это счётчик проверок, а не замер FPS/MSPT: реальный выигрыш зависит от сборки.

## Известные конфликты / замечания
- **Moonrise, Lithium, C2ME, VMP** (реализуют свои оптимизации поиска сущностей) в этой разработке **не устанавливались и не
  проверялись**. Мод при старте пишет warning, если находит их. Падать он не должен: при чужой замене `EntityLookup` мод откатывается на ваниль,
  но выигрыша от двух оптимизаций сразу не будет, а порядок выполнения HEAD-инъекций определяется приоритетом миксинов.
- Приоритет задан **1500** (в `entity_collision_grid.mixins.json` и в `@Mixin(priority = 1500)`). Это не `fabric.mod.json`:
  приоритеты миксинов в Fabric задаются в mixin-конфиге, а не в манифесте мода.
- Миксины в `Entity` (только `setBoundingBox`, плюс поле-хранилище) могут пересекаться с Meteor Client/Moonrise, но разные методы
  совместимы; жидкостные методы не трогаются.
- Порядок сущностей в списке может отличаться от ванильного (набор — тот же).
- Интеграция в Sodium проверена компиляцией против Sodium 0.8.14; на самом клиенте с видеокартой я её не запускал.
